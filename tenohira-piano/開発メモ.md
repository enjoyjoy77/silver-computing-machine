# てのひらピアノ 開発メモ

iPhone の Safari で弾くための、広告のないブラウザピアノ。88 鍵を縮めて並べず、要る音域だけを指の置ける太さで出す。
初版は演奏部分だけ。押して、狙った長さだけ鳴らして、確実に止められること。和音ボタンや練習機能は、ここが固まってから足す。

## ファイル

- `index.html` … 画面・音・指の扱い。ブラウザだけで動く
- `piano-core.js` … 中身。音名、鍵盤の並べ方と当たり判定、音源の割り当て、録音の整え方、MIDI 書き出し、設定の検査。node でも読める
- `samples/` … ピアノの音源 30 本（MP3、合計 2MB）と、その利用条件 `README-salamander.txt`
- `sw.js` … 画面をキャッシュして、通信なしでも開けるようにする
- `test/core.test.js` … `node tenohira-piano/test/core.test.js` で走る

## 初版に入っているもの

一段鍵盤（横向き白鍵 10 個・縦向き 7 個が初期値、設定で変えられる）、指を何本でも同時に、音域の移動（白鍵 1 つ・1 オクターブ）、
音域を 3 つまで登録して呼び出し、ペダル（押している間／押すたびに入・切）、全消音、録音・再生・MIDI 書き出し、
設定と録音の保存とバックアップ、画面端の余白（3 段階）、音の遅れを耳で比べる確認パッド。

## 音源

Salamander Grand Piano（ヤマハ C5、Alexander Holm 録音、CC BY 3.0）。Tone.js が公開している MP3 版
（github.com/Tonejs/audio の `salamander/`）をそのまま置いている。短三度おきの 30 本で、どの鍵も 1 半音以内の音源を
再生速度で上下させて鳴らす。強さの段（ベロシティレイヤー）は 1 つだけ。

読み込んだあとに手を入れている（ファイルは元のまま）。

- 左右を混ぜて 1 本にする。iPhone のスピーカーではほぼ差がなく、メモリが半分で済む
- 頭の無音を詰める。MP3 の先頭の詰め物と録音の間で、元は 10〜22ms あった。詰めたあとは最初の音まで 0〜5ms
- 8 秒より長い分は最後の 1.5 秒で消えていくように切る。低音は元が 25 秒あり、全部持つとメモリが 1.5 倍になる
- 音量をならす。隣どうしで最大 7dB 違った（A3 と C4 など）。最初の 0.3 秒の音量を音の高さで回帰した線に、
  四分の三だけ寄せる倍率を `SAMPLE_GAIN` に直書きした（作り直す手順: ffmpeg で
  モノラルに展開 → 頭の無音を除いて 0.3 秒の RMS → log(RMS) を MIDI 番号で一次回帰 → 回帰の傾きを半分にした線 ÷ 実測 → 0.75 乗）

読み込みは、いま表示している音域に近い順に 3 本ずつ。表示している音域の分がそろった時点で鍵盤を出し、残りは裏で読む。
音域を動かしたら、残りの順番を並べ直す。読めなかった音源は 3 回まで取り直す。それでもだめなら近い音源の高さを変えて代わりに鳴らし、
「情報」から読み直せるようにした。1 本も読めないときだけ、起動画面で「もう一度読み込む」と「簡易音で始める」（三角波の合成音）を出す。

## 音の仕組み

声（1 音）は「音源 → 止音用のゲイン → 全体の音量」。押した瞬間に `start(0)`、離したら止音用のゲインを `setTargetAtTime` で落とす
（時定数は低音 0.11 秒・中音 0.08 秒・高音 0.06 秒）。同じ鍵を打ち直したら前の声は 12ms で消す。声は 40 までで、超えたら離した声から消す。

和音を重ねて 1 を超えたときだけ丸める波形整形（WaveShaper）を出口に置いた。DynamicsCompressor は先読みで数 ms 遅れるので使わない。
残響は雑音を減衰させた響きを畳み込む。切のときは畳み込みの手前で配線を外して、処理そのものを止める。
離した後の響きは、弱で約 −22dB、強で約 −15dB（鳴っている間の音に対して）。

指で弾く音・録音の再生・遅れ確認のパッドは、それぞれ別の「通り道」（`Channel`）で持つ。押さえている指（holder）とペダルの状態を
通り道ごとに持つので、再生中に自分で弾いても互いの音を止めない。全消音は全部まとめて止める。

強弱「押す位置で変える」は、鍵の奥（上）を 0.35、手前（下）を 1.0 にして、弱いほど高い倍音を削るローパスを挟む。初期値は一定（0.8）。

遅れについては数値を約束しない。`latencyHint: 'interactive'` はブラウザへのお願いで、保証ではない。
確認パッドの下に、ブラウザが申告する `baseLatency` と `outputLatency` を出すだけにした（取れない環境では「取得できません」）。
Bluetooth かどうかは判定しない。

## 指の扱い

`pointerdown` で鳴らす（click は待たない）。指ごとに `pointerId` で押した鍵を覚え、離した指の音だけを止める。当たり判定は
DOM ではなく `piano-core.js` の `hitTest` で計算する（黒鍵が上に乗っているので先に調べる）。

- 初期設定では、押したまま指がずれても最初の音のまま。「ずれた先を鳴らす」にしたときだけ、滑らせた先の鍵に移る
- 音域を動かしても押さえている音は変わらない。滑らせる設定でも、音域を変える前から押していた指は新しい音域に移らない
- `pointercancel`・`lostpointercapture`・画面の回転・ウィンドウのフォーカスが外れたときは、押さえている音を離す
- 画面を離れた（`visibilitychange` で hidden、`pagehide`）ときは全消音。録音中なら録音もそこで止めて保存する
- 演奏面は `touch-action:none`。iOS の長押しメニュー・拡大鏡・ダブルタップ拡大は、`touchstart` の preventDefault と
  `-webkit-user-select`・`-webkit-touch-callout` で止める。設定画面は縦にスクロールできるよう、ここだけ外している

## iPhone で気をつけたこと

- 消音スイッチ（マナーモード）が入っていると、Web Audio はふつう鳴らない。`navigator.audioSession.type = 'playback'`
  （iOS 16.4 以降）で鳴るようにした。古い iOS では無音の `<audio>` を流しておく定番の手を使う
- ただし `playback` だと、ほかのアプリの音楽が止まる。設定の「ほかのアプリの音楽」で `ambient`（重ねて鳴らす。消音モードでは鳴らない）
  に切り替えられる。`navigator.audioSession` がないブラウザではこの項目を出さない
- 電話などで音が止まると `AudioContext` が `interrupted` になる。戻ってきたら起こし直すが、iOS は指を離したとき（`pointerup`）でないと
  起こさせてくれないことがあるので、`pointerdown` と `pointerup` の両方で `resume()` する。止まっている間は「鍵盤に触れると戻ります」と出す
- 安全領域（`env(safe-area-inset-*)`）に、さらに余白を足す。ホームに戻る操作を無効にはできないので、指がかかりにくい所に鍵盤を置くだけ
- 横向きで操作列が 2 段に折れたら、JS が `compact` を付けて文字を減らし 1 段に戻す（鍵盤の高さを守るため）

## 保存

設定は `localStorage` の `tenohira-piano:settings`、録音は `tenohira-piano:recordings`。どちらも読み書きを try で包み、
壊れていたら `sanitizeSettings`・`sanitizeRecording` で初期値に戻す。端末内の保存は永久ではないので、「録音」画面から
設定と録音を JSON で書き出し、読み戻せる（同じ id の録音は重ねない）。

音源はページ側が Cache Storage（`tenohira-piano-samples-v1`）に入れていく。初回に Service Worker がまだ効いていなくても
二重に落とさないため。`sw.js` は画面のファイルを `tenohira-piano-shell-v1` に入れ、音源は同じ音源用キャッシュから先に探す。
「情報」に保存の状態（音源 n/30・画面）を出す。画面を直したら `sw.js` の SHELL の番号を上げる（上げ忘れても 2 回目の起動で新しくなる）。

## 録音の形

1 つの出来事は `[時刻ms, 種類, 番号, 強さ]`。種類は 1=押した 0=離した 2=ペダル（番号が 1 か 0）。
`finishEvents` で、押しっぱなしの音を最後に閉じ、同じ鍵の二度押しの間に「離した」を挟み、先頭の待ち時間を 0.2 秒に詰める。
再生は 25ms ごとに 0.2 秒先までの出来事を音の時計（`currentTime`）で予約する。MIDI は SMF 形式 0、480 tick/拍、120BPM 固定
（拍に合わせて弾いたわけではないので、小節線は目安にならない）。音声ファイル（m4a・wav）での書き出しは次の段階。

## 確かめたこと

node のテスト（13 件）。音名、白鍵の数え方、上端・下端の寄せ、黒鍵の並びと当たり判定、強さ、音源の割り当て（どの鍵も 1 半音以内）、
録音の閉じ方、MIDI のバイト列、設定と録音の検査。

Playwright（Chromium、iPhone 相当の大きさ・タッチ）で、指 3 本の和音、1 本だけ離す、押したまま音域を動かす、黒鍵、ペダル（押している間・入切）、
滑らせ（初期設定・滑らせる設定）、録音 → 再生 → 全消音、画面を離れたときの全消音、残響あり、縦向き・横向き・iPhone SE の横向き、
音源が全部取れないとき、一部取れないとき、一度開いてから通信を切って開き直したとき。

## 実機で確かめること（まだ）

Chromium では iOS の Safari の癖は再現できない。iPhone で次を見る。

- 和音（3〜5 本）、同じ鍵の連打、押したまま指がずれたとき、回転、ホームに戻って戻ってきたとき、電話・アラームの後
- 消音スイッチを入れたまま鳴るか。「重ねて鳴らす」で音楽アプリと一緒に鳴るか
- 横向きで白鍵 10 個が押しやすいか（多い・少ない）。黒鍵の幅と長さ。画面端の余白は標準で足りるか
- 本体スピーカー・有線・Bluetooth で確認パッドを叩き比べたときの遅れ
- ホーム画面に追加したとき（standalone）の MIDI 保存とバックアップ書き出し（共有シートが出るか）
