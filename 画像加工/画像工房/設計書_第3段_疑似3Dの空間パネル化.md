# 設計書: ミタテ第3段 — 疑似3D(ゆらゆら/傾け/多層/ライティング)の空間パネル化

作成: 2026-07-05 / 対象: mitate.html のみ / 完了時 rev: v2 rev5
親計画: 改修計画_ミタテ操作性_2026-07-05.md「第3段」

## 0. ゴール(1行)

**ゆらゆら・傾け・多層・ライティングを、AR/VRで「空間に浮かぶ実寸パネル」として、レリーフと同じ操作(つかむ・回す・大きさ・呼び戻し・手モデル)で楽しめる。**

## 1. 最重要の設計方針: 2D表示は一切いじらない

PC・スマホの2D表示(全画面quad + 多層layerGroup + ortho/perspカメラ)は現状うまく動いている。**壊さないことを最優先**(教訓lessons.md: 動いているものを無テストで作り替えない)。よって:
- 2D用の `quad` / `layerGroup` / 2Dレンダリング分岐は**そのまま残す**
- XR用に**別の専用オブジェクト**を新設し、XR没入中のパスの中だけで使う

## 2. 各モードの「空間版」の作り

| モード | 空間での姿 | 実装 |
|---|---|---|
| ゆらゆら(wiggle) | ひとりでに揺れる「動く絵画」 | panelMesh を時間で自動視差 |
| 傾け(parallax) | 覗き込むと中が動く「窓」 | panelMesh を**頭の位置**で視差(2Dの指ドラッグの代わり) |
| ライティング(light) | 光が回り陰影が流れる板 | panelMesh の陰影計算を強化(下記4) |
| 多層(layers) | 層が奥行きを持つ「ジオラマ箱」 | xrLayerGroup(層を実寸で重ねる。頭を動かすと自然に視差) |

### 新オブジェクト(start()で生成。高さ1m基準=レリーフと同じ。root.scale=sizeCm/100で実寸化)
- `panelMesh`: `PlaneGeometry(aspect, 1)` + `panelMat`。panelMat は2Dの quad の陰影/視差ロジックを流用しつつ、(a)通常のMVP頂点シェーダ (b)fitUv廃止(UVは板に直接)。テクスチャは imgTexLinear(2Dと同じ見え)。専用uniforms `panelU`
- `xrLayerGroup`: 2Dと同じ層シェーダを高さ1mで6枚。`buildLayersInto(group,height,tex)` に共通化して2D/XR両方から呼ぶ

### 配置とグラブ
- panelMesh/xrLayerGroup は、そのモードがXRで有効な時だけ `tiltGroup` の子にする(レリーフと同じ階層=同じ操作対象)
- `grabTarget` 変数を導入。onGrab はこれを raycast(層グループは再帰intersect)。setMode/モード切替で更新
- panel/layerのメッシュも `reliefMesh.position.y = 0.5` と同じく足元を原点に立てる(呼び戻しの床置き・実寸と整合)

## 3. XR中のモード切替とXR突入

- **2D画面でモードを選んでから AR/VR を押す** = 確実な主ルート。startAR/startVR の「強制relief」をやめ、選択中モードのまま突入する
- 突入時ヘルパ `enterXR(mode)`: `scene.remove(quad); scene.remove(layerGroup); scene.add(root)` を保証してから、モードのオブジェクトを tiltGroup に付ける(2Dで疑似モードだと root がシーンに無いため必須)
- **没入中の切替**: スティック押し込み(buttons[3])のエッジ(グリップ非押下時のみ=回転と混ざらない)で relief→ゆらゆら→傾け→ライティング→多層→relief を循環。没入中はDOMメニューが見えないため、これが唯一の切替手段。※画面内の文字表示は無い(視覚の変化がフィードバック)。この制約はユーザーに明記する

## 4. ライティング強化(「変化が見えない」の解消)

現状 `n=normalize(vec3((dl-dr)*uAmt*6.0,...,1.0)); rgb=col*(0.55+diff*0.9)` は、法線の摂動が弱く周囲光0.55で陰影が埋もれる。強化:
- 勾配スケール ×6 → **×18**(凹凸をはっきり)
- 周囲光 0.55 → **0.35**
- **鏡面ハイライト追加**: `H=normalize(L+vec3(0,0,1)); spec=pow(clamp(dot(n,H),0,1), 24.0)*0.5`
- `rgb = col*(0.35 + diff*1.1) + spec`
- **2Dの quad にも同じ強化を適用**(2Dでも「変化が見えない」と言われたため)。GLSLミスは即エラー表示になるので実装後に2D light切替でエラー無しを確認

## 5. 頭トラッキング視差(panel の parallax)

XRフレーム毎、モード別に panelU.uShift を更新:
- parallax: カメラ(頭)位置を panelMesh のローカル座標へ変換し、板中心からのx/yずれを正規化 → uShift(符号は定数 `PANEL_PARALLAX_SIGN`、実機で逆なら反転)
- wiggle: `uShift = (sin(t*f), 0)`(頭に依らず自動)
- light: uLightDir を時間回転
- 毎フレームの new を避け、一時ベクトルを使い回す(酔い対策)

## 6. 壊しやすい所(実装時チェック)
- setMode は「2Dパス(現状のまま)」と「XRパス(新規)」を `renderer.xr.isPresenting` で分岐。2D側のコードは1行も変えない
- onGrab の raycast 対象を reliefMesh 固定から grabTarget へ。relief時は grabTarget=reliefMesh を維持
- XR終了時: panel/xrLayer を tiltGroup から外し、grabTarget を reliefMesh に戻し、2Dの scene 構成に戻す(setMode(mode)を呼べば復元)
- 実寸cm(sizeCm)は root.scale なので panel/layer にも自動で効く(1m基準で作れば正しい)
- GLBエクスポートは reliefMesh 単体なので無影響

## 7. Quest確認項目(番号で回答)
1. 右上revが「v2 rev5」か
2. 2D画面(PC/スマホ)の5モードが今まで通り動くか(退行が無いか)
3. 2D画面でゆらゆらを選んでVRに入ると、目の前に「揺れる絵」が浮かぶか
4. スティック押し込みでモードが循環するか(relief→ゆらゆら→傾け→ライティング→多層)
5. 傾け(窓)で、頭を左右に動かすと絵の中の視点が動くか。方向は自然か(逆なら「逆」と)
6. 多層が奥行きのある「ジオラマ箱」に見えるか
7. ライティングで今度こそ陰影の変化が見えるか(2D・XR両方)
8. パネルも掴む/回す/大きさ変更/呼び戻し/手モデルが効くか(レリーフと同じ操作)
9. 各モードで動画保存・従来機能に退行が無いか
