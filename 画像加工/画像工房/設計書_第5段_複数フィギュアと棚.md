# 設計書: 第5段 — 複数フィギュア(棚コレクション + AR内で並べて比べる)

作成: 2026-07-06 / 対象: common.js, depth.html, mitate.html / 完了時 rev: mitate rev7
ユーザー選択: 「棚+ARパレット」方式(2026-07-06)

## 0. ゴール(1行)
**用意した複数のフィギュアを「棚」に貯め、AR空間に何体でも出して、一体ずつ独立に掴んで並べて比べられる。**

## 1. 方針と割り切り(実機で確認できないので特に慎重に)
- **重いAI(深度生成)はAR中に回さない**。新規フィギュアの準備(切り抜き→深度)はARの外。既に用意した棚の中身をAR内で出し入れ・配置する。
- **複数体は「3Dレリーフ(立像)」に対して**。疑似3D(ゆらゆら/傾け/多層/ライティング)は"1枚の作品"体験なので**単体のまま**(選択中の1体に適用)。フィギュアを部屋に並べる用途=立像なので、複数化は立像だけで十分。
- 既存の単体動作を壊さない。**items配列でN=1のとき現状と同じ挙動**になるよう一般化する(後方互換)。
- 段階を割る: **段階A=複数配置+個別操作(まず本命)** / **段階B=AR内パレットで出し入れ・新規往復**。段Aを実機で固めてから段Bへ。

## 2. データ構造: 棚(コレクション)= IndexedDB
common.js に追加(既存 handoff とは別ストア `figures`):
- `figuresAdd({name, image:Blob, depth:Blob}) -> id`(idは時刻+連番。使い回さない)
- `figuresAll() -> [{id, name, image, depth, ts}]`(古い順)
- `figuresRemove(id)`
- `figuresClear()`
- 既存の handoffSend/Take(source/depth)は「1回だけの受け渡し」として残す(kiritori→depth の切り抜き受け渡しに使用)

## 3. depth.html の変更
- 「🧊 立体で見る」を押したとき: 現状の handoffSend(source/depth) の代わりに、**figuresAdd({name, image:元画像Blob, depth:深度PNG Blob})** で棚に追加 → mitate.html へ遷移。
- これで深度を作るたびにフィギュアが**貯まる**(上書きされない)。
- kiritori→depth の入口(handoffTake source)は不変。

## 4. mitate.html の2D画面
- 起動時に `figuresAll()` で棚を読む。
- 棚が空で、旧来の単体handoff(source+depth)が来ている場合は、それを1体としてfiguresAddしてから読む(後方互換・従来フローが切れない)。
- 一覧サムネイル表示: 各フィギュアに「表示/非表示(ARに出すか)」チェックと「削除」。
- 「立体で見る」= チェックした(既定は全部)フィギュアでシーンを組んで表示。

## 5. mitate.html のシーン再設計(段階Aの核)
### item 構造(現状の単体stateを1体分に束ねる)
```
item = { id, name, aspect,
  imgTexSRGB, imgTexLinear, depthTex, depthMap, alphaMap,  // テクスチャ類
  group,      // = 現状のroot相当: 位置・大きさ(sizeCm/100 × userScale)・水平回転yaw
  tiltGroup,  // 前後傾き
  reliefMesh, // 立像
}
```
- 全 item.group を scene 直下に置く。
- `buildItem(figure)` で1体分を構築(現状の buildRelief 相当をitem用に)。
- 疑似3D用の panelMesh/xrLayerGroup は**シーンに1つだけ**(選択中itemのテクスチャで作り直す)。

### 操作(grab/pinch/rotate)の item 対応
- `grabbed = [null, null]`(コントローラー/手 i が掴んでいる item)
- `activeItem`(最後に触れた item。回転・疑似3Dの対象)
- **onGrab(i)**: 全 item.reliefMesh を raycast → 当たった item を grabbed[i] に。activeItem に。
  - 反対の手が同じ item を掴んでいれば **beginPinch(item)**(その1体を両手で拡縮回転)
  - そうでなければ **controllers[i].attach(item.group)**(片手で移動)
- **onRelease(i)**: grabbed[i] を解除。pinch中でその item なら endPinch。親付けを戻す(scene.attach + flattenYaw)。
- **beginPinch/updatePinch/endPinch**: `pinch = { item, ... }`。対象は pinch.item.group。差分適用は現状のまま。
- **flattenYaw(group)**: 引数の group を yaw だけに(現状の flattenRootYaw を汎用化)。
- **グリップ+スティック回転**: activeItem.group.rotation.y と activeItem.tiltGroup.rotation.x を回す(現状の root/tiltGroup を activeItem に)。「置いてある時だけ」ガードは group.parent===scene で判定。
- **呼び戻し(A/B/X/Y)**: **全 item を目の前に横一列で並べ直す**(迷子回収)。各itemの傾きも0に。

### 初期配置 placeItems()
- AR/VR開始の最初のフレーム(pendingPlace)で、**表示中の全itemを視線の先に横一列**に。
  - 頭の位置・向きから正面を出し(既存placeInFrontの頭読み取りを流用)、左右に item を実寸幅ぶん間隔で配置。中心が視線の先1.2m。各itemはこちら向き、VRは床上/ARは目線やや下。
  - AR床置き(reticle+select)は「まとめて置く」= 選択した床位置を基準に横一列。

### 疑似3Dモード(単体)
- パネル/多層は activeItem のテクスチャで build。パネル表示中は relief群を隠す。relief に戻すと再表示。
- xrAttach/enterXR/setMode を items 対応に(relief=全item表示、疑似=activeItemのパネルのみ)。

## 6. 段階B(次段): AR内パレット
- 世界空間の3Dパネル(CanvasTextureに棚サムネ)を目の前に出し、指差し+つまみ/トリガーで各フィギュアの「出す/しまう」をトグル。
- 「＋新規」= ARを一度終了して kiritori へ(準備後、棚に増えて戻る)。
- パレットの出し入れはボタン(スティック押し込み長押し 等)で。※段Aのモード循環(スティック押し込み)と衝突しないよう割当を再整理する。

## 7. 壊しやすい所 / 実機確認項目
- 単体(N=1)で現状と同じに動くこと(後方互換の回帰)。
- GLB書き出し・動画保存は activeItem 対象に。
- 2D画面の疑似3D・relief表示が従来通り(2Dは単体表示でよい。複数はAR/VRの体験)。
- Quest確認: ①棚に複数貯まるか ②ARで複数体が横一列に出るか ③各体を別々に掴んで動かせるか ④両手で1体を拡縮回転できるか ⑤呼び戻しで全部目の前に戻るか ⑥1体を疑似3D(ゆらゆら等)にして戻せるか。

## 9. 今後の要望(未着手・2026-07-10ユーザー提案)
- **彫刻モード(sculpt)**: AR/VRで、掴む/拡縮とは別の操作モードとして、レリーフの**つまんだ部分だけを上げ下げ**(深度メッシュの局所変形)。ブラシ半径(効く範囲)も可変に。大きめの新機能=専用段で。実装案: reliefGeoの頂点を、コントローラー先端に近い頂点ほど法線(Z)方向へ押し引き。ブラシ半径・強さのUIをXR内に。undo検討。
- **コントローラーの手モデル**: 現状の低ポリ手が「微妙」。ユーザーはハンドトラッキングの実物メッシュ流用を希望。ただし**トラッキングmeshは実際の手関節が要る**ためコントローラーでは駆動不可(静止GLB=バインドポーズの平手になる/実物Questコントローラーモデルなら無調整で写実)。→ユーザーに選択肢を確認してから。
