## 1. 機能A: グリップ+スティック回転

### 1-1. 操作仕様(ユーザー視点)

| 状態 | スティック | 起きること |
|---|---|---|
| グリップ(中指のボタン)を握っている間 | 左右に倒す | フィギュアがその場で水平回転。倒した方向に回る(右に倒す=正面が右へ流れる) |
| 同上 | 上下に倒す | 前後に傾く(上=奥へ倒れる)。**±45度まで**で止まる |
| グリップを離している | どちらも | 何も起きない(誤操作防止) |

- 回転の速さ: スティックを全部倒して**1秒で約90度**(水平)。傾きは1秒で約70度
- スティックの遊び: **±0.15**。軽く触れただけでは動かない。遊びを超えた分だけ滑らかに効く(いきなり最高速にならない)
- 両手同時にグリップ+スティックの場合: **倒し量が大きい方の手だけ**を採用(2倍速になる事故を防ぐ)
- **両手ピンチ(大きさ変更)中はスティック回転を無効**(2系統の回転が喧嘩しないように)
- 呼び戻しボタン(A/B/X/Y)を押すと、**傾きもまっすぐにリセット**される(第1段の仕様を継承)

### 1-2. 技術設計

**入力の読み方**: WebXRのボタンイベントには「スティックの値」が無いので、毎フレーム `session.inputSources` を回して gamepad を直接読む(第1段の pollRecallButtons と同じ場所に統合し、1フレーム1ループにする)。

- Quest Touchの配列位置(xr-standard-gamepad準拠):
  - `buttons[0]`=トリガー / `buttons[1]`=**グリップ** / `buttons[3]`=スティック押し込み / `buttons[4]`=A・X / `buttons[5]`=B・Y
  - `axes[2]`=スティック左右 / `axes[3]`=スティック上下(**axes[0][1]はタッチパッド用で空**。ただし `axes.length < 4` の機種フォールバックとして axes[0][1] を読む)
- 遊び処理: `v = (|axis|<0.15) ? 0 : sign(axis)*(|axis|-0.15)/0.85`(0〜1に正規化)
- 回転の適用(毎フレーム):
  - 水平: `yawGroup.rotation.y -= x * 1.6rad/s * dt`
  - 傾き: `tiltGroup.rotation.x = clamp(tilt + y * 1.2rad/s * dt, -45°, +45°)`
  - dt はフレーム間秒。**上限0.05秒でクランプ**(フレーム落ち時に一気に回るのを防ぐ)

**構造変更(重要)**: 現在は `root > reliefMesh` の2階層。回転を素直に載せるため3階層にする:

```
root(位置・大きさ・水平回転 = つかみ/ピンチ/呼び戻しの対象。従来どおり)
 └ tiltGroup(前後の傾きだけを持つ。新設)
     └ reliefMesh(足元中心。従来どおり)
```

- 水平回転は root.rotation.y にそのまま加算(つかんでコントローラーの子になっている間も、ローカル回転として自然に効く)
- 傾きを root に直接載せない理由: root.rotation.x をいじると、両手ピンチの水平回転計算(rotation.y だけ読む前提)や呼び戻しの quaternion.identity() と衝突して姿勢が壊れるため。傾きは専用の子に隔離する
- 第3段の空間パネルも同じ tiltGroup の中に入れる(操作の一貫性)

**毎フレームのオブジェクト生成禁止**(酔い対策の定石): ループ内で new しない。一時変数は既存の使い回しパターンに従う。

### 1-3. ここで壊しやすい既存機能(実装時に必ず確認)

- 両手ピンチの回転基準 `pinch.r0`(root.rotation.y を読む)→ 水平回転をrootに載せる限り無影響
- 呼び戻し placeInFront() → `tiltGroup.rotation.x = 0` を追加すること
- XR終了時の姿勢リセット → tiltGroup も 0 に戻すこと
- GLB書き出し → reliefMesh 単体を書き出しているので無影響

## 2. 機能B: コントローラー用の手モデル

### 2-1. 見た目の仕様

- **日本人の普通の肌色**: ベースカラー `#e8c0a0`(明るめのベージュ)。つや消し(roughness 0.85・metalness 0)、テカり・爪・しわ・血色表現なし。**フラットでさらっとした、よくあるアバターの手**
- 形: 成人男性の手を簡略化した低ポリ。**手首まで**(腕は作らない)
- 大きさ: 実物大(手のひら幅 約8.5cm・中指つけ根から先端 約7cm・手首直径 約6cm)
- 左右: 右手を定義し、左手はX軸ミラーで生成(作りを1つに保つ)

### 2-2. 部品構成(外部3D素材なし・コードで組む)

| 部品 | 形 | 寸法(mm) | 個数/片手 |
|---|---|---|---|
| 手のひら | 角の丸い箱(Box) | 85×28×90 | 1 |
| 指(人差し〜小指) | カプセル | 半径9・長さ 62/70/64/50 | 4 |
| 親指 | カプセル | 半径10・長さ58 | 1 |
| 手首 | 円柱 | 半径30・長さ40 | 1 |

- 片手7部品×両手=**14描画**。性能予算(1フレーム100描画目安)に対して誤差レベル
- 指は手のひら前縁から自然に**15度ほど曲げた"脱力ポーズ"**で配置。親指は内側45度
- 指を関節で分割しない(1本もの)。リアルさより「手がそこにある」ことが目的

### 2-3. 取り付けと動き

- 取り付け先: `renderer.xr.getControllerGrip(i)`(**握り位置**の空間。レーザーを出している照準用の空間とは別物なので混同しない)
- 向き合わせ: グリップ空間は「手のひら中心が原点、握りの軸が概ねZ」。指先を-Z方向やや下向き、手のひらをコントローラー側に向ける回転オフセットで合わせる。**このオフセット角3つ(X/Y/Z)は定数として1箇所にまとめる**——実機で「角度が変」となったらそこだけ直せばよい設計にする
- **トリガーを引くと指4本が約35度曲がる**(離すと戻る)。カクつかないよう1フレームではなく約0.1秒かけて曲げる。親指は動かさない(簡素に)
- レーザー線は従来どおり照準側に表示し続ける

### 2-4. 表示のオン・オフ(事故防止)

- XRセッション中だけ表示。終了時に非表示(グリップ空間は非XR時に原点に固まるため、消さないと画面中央に手が置き去りになる)
- コントローラーの `connected` / `disconnected` イベントで個別に表示切替。**Questの「手とコントローラの自動切替」でコントローラーを置くと disconnected が来る**——このとき手モデルを消さないと、空中に手が固まって残る(第4段の素手対応の前でも、この防御だけは今回入れる)

### 2-5. リスクと逃げ道

- **一番の不確定要素は 2-3 の向き合わせ**。エミュレータと実機で印象が変わりうる。1回で完璧を狙わず、「実機を見て角度定数を直す」1往復を織り込む(確認項目に"手の角度がおかしくないか"を入れてある)
- 手が大きすぎ/小さすぎと感じる場合に備え、寸法も定数化しておく
- 万一「手が邪魔」となったら、UIは増やさず**非表示にする定数**を用意(将来設定化するかは使ってから)

## 4. Quest確認項目(実機テスト、番号で回答)

1. 右上のrevが「v2 rev4」か
2. グリップ+スティック左右で、その場でくるくる回るか。**回る向きは直感と合っているか**(逆なら符号を反転するので「逆」と言うだけでOK)
3. グリップ+スティック上下で前後に傾き、45度で止まるか。倒しすぎて戻れなくなることはないか
4. 呼び戻しボタンで傾きもまっすぐに戻るか
5. 両手に肌色の手が見えるか。**角度・左右・大きさに違和感がないか**(あれば「親指が外向き」「手が上向きすぎ」など言葉で)
6. トリガーで指が曲がるか
7. 手がフィギュアより手前にあるとき、手前に見えるか(この段の主目的)
8. コントローラーを机に置いた(または素手に切り替わった)とき、空中に手が置き去りにならないか
9. 従来機能の退行確認: つかむ/両手で大きさ変更/床置き(AR)/呼び戻し、が今まで通りか

## 5. やらないこと(この段では)

- 素手のハンドトラッキング(第4段)
- 疑似3DモードのXR化(第3段)
- 手の見た目の作り込み(爪・しわ・関節分割)。「そこに手がある」以上の品質は目的外
