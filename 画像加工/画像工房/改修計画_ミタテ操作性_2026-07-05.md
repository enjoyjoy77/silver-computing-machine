# ミタテ改修計画(Quest実機フィードバック反映) 2026-07-05

ユーザーがQuest 3で実際に使った感想に基づく改修。4段階で進め、段ごとにrevを上げて実機確認を挟む。
(いっぺんに全部変えると、壊れたときにどれが原因か分からなくなるため — 過去の教訓)

## 決定事項(ユーザー確認済み)

- 深度づくりのAIモデルは**軽い方(Depth Anything V2 small)一本化**。重い方(base)はQuestで耐えられない+非商用ライセンスのため削除
- 3Dの手の色は**日本人の肌色**(ベージュ系マット、リアルすぎない質感)
- **ライティングモードは残す**。AR/VR対応も他モードと同様に行い、効きが弱い問題を改善。使ってみて駄目なら後で削除を再検討
- ハンドトラッキング(素手操作)は最終段。Quest側設定「手とコントローラの自動切替」ONが前提

## 操作の全体像(完成時)

| 入力 | 動作 |
|---|---|
| トリガー(人差し指) | レーザーで指してつかむ・移動。両手同時で大きさ変更+水平回転(現状のまま) |
| **グリップ(中指)+スティック左右** | **その場で水平にくるくる回転**(新規・第2段) |
| グリップ+スティック上下 | 前後に傾ける(新規・第2段。不要なら後で外す) |
| **A/X・B/Yボタン** | **「目の前に呼び戻す」**(新規・第1段) |
| 素手のつまみ(第4段) | トリガーと同じ扱い。両手つまみで大きさ・回転 |

## 第1段: 深度一本化+出現位置(rev3) ← 今回実施

### 1-A 深度づくり(depth.html)
- モデル選択カードを撤去し、small固定。「準備する」ボタンだけの1段構成に
- index.html のライセンス早見表から base の行を削除(非商用の地雷が完全になくなる)

### 1-B 出現位置(mitate.html)
問題: VRは「部屋の境界設定の原点」基準で置いていたため、立ち位置や向きと無関係な場所に出ていた。

- **AR/VR開始の最初のフレームで、実際の頭の位置と向きを読み、視線の水平方向1.1m先に出す**
  - VR: 床の上(足元が床につく)。ARの配置前プレビュー: 目線のやや下(中心が目の高さ−20cm)に浮かせる
  - 出現時は必ずこちらを向く(正面がユーザーへ)
- **呼び戻しボタン**: コントローラーのA/X・B/Yどれでも、押した瞬間に同じ「目の前1.1m」へ戻ってくる。「あれどこだ?」の保険
- ARの床置き(リングにトリガー)は今まで通り。呼び戻し後もつかみ直し可能

### 第1段のQuest確認項目
1. 深度づくり: モデル選択が消え、「準備する」→画像ドロップ→深度完成まで通るか
2. ミタテVR: 開始した瞬間、自分が向いている方向の床の上・1mちょっと先にフィギュアが立っているか
3. ミタテAR: 開始した瞬間、目の前に浮かんで見えるか(その後リングで床置きできるか)
4. わざと遠くへ投げてから A または B ボタン → 目の前に戻ってくるか
5. 画面右上のrevが「v2 rev3」になっているか(古い版を見ていないかの確認)

## 第2段: 回転操作+コントローラー用の手モデル(rev4)

**詳細設計書あり → 設計書_第2段_回転操作と手モデル.md**(実装はそちらに従う)

### 2-A グリップ+スティック回転
- グリップボタン(中指)を握っている間だけ、スティック左右=水平回転(秒速約90度)、上下=前後の傾き
- スティックの遊び(±0.15)を設け、軽く触れただけでは回らない
- 実装: 毎フレーム `session.inputSources` の gamepad を読む(ボタン1=グリップ、軸2=左右、軸3=上下)。第1段で作るボタン監視の仕組みを流用

### 2-B 手モデル
- 外部素材なし、部品(角丸の箱+カプセル)を組んで作る低ポリの成人男性の手(手首まで)。左右対称ミラー
- 色: 日本人の肌色ベージュ(目安 #e8c0a0 前後、マット質感、テカりなし)
- コントローラーの「握り位置」(grip空間)に装着。トリガーを引くと指が軽く曲がる
- レーザー線は今まで通り表示(狙いに必要)

### 第2段のQuest確認項目
1. 両手に手のモデルが出るか。向き・左右が合っているか(親指が内側)
2. 手がフィギュアより手前にあるとき、ちゃんと手前に見えるか(今回の主目的)
3. グリップ+スティック左右でその場回転するか。腕を動かさず1周できるか
4. トリガーで指が曲がるか
5. 傾け(スティック上下)は使い物になるか(不要なら削除するので感想を)

## 第3段: ゆらゆら/傾け/多層/ライティングの空間パネル化(rev5)

**詳細設計書+実装記録あり → 設計書_第3段_疑似3Dの空間パネル化.md**(2026-07-05にrev5として実装・多角レビュー実施)

現状の疑似3Dは「画面全体に貼る」作りでXRに出せない。**「空間に浮かぶ額縁パネル」**として再構築する。

- パネルはレリーフと同じ「つかむ・回す・大きさ変更・呼び戻し」の対象(操作を覚え直さなくてよい)
- 大きさは実寸cm入力を共用(例: 30cm=ポスター風)
- 各モードの空間版:
  - **ゆらゆら**: 時間で自動的に視差が揺れる「動く絵画」。飾って眺める用途の本命
  - **傾け**: 指なぞりの代わりに**頭の位置**で絵の中の視点が動く「窓」。覗き込むと奥が見える
  - **多層**: 層構造をそのまま空間に置く「ジオラマ箱」
  - **ライティング**: 陰影の計算を強化(現状は凹凸の計算が弱く「何も変化していない」ように見える。強さの効きを数倍に+ハイライト追加)した上で空間に置く
- 2D画面(PC・スマホ)の従来表示はそのまま残す

### 第3段のQuest確認項目
1. AR中にモード切替でパネルに変わるか(レリーフ⇄ゆらゆら⇄傾け⇄多層⇄ライティング)
2. ゆらゆらパネルを部屋に飾って「動く絵画」に見えるか
3. 傾けパネルを左右から覗き込むと、絵の中の視点がついてくるか
4. ライティングは今度こそ変化が見えるか(それでも微妙なら削除を検討)

## 第4段: ハンドトラッキング(素手操作)(rev6)

- AR/VRの開始オプションに手の認識を追加(optionalなので、非対応でも今まで通り動く)
- 素手のとき: Questが認識した**本物の手の形と同期した3Dの手**を表示(第2段の作り物の手はコントローラー使用時のみ)
- 操作: 親指+人差し指のつまみ=トリガー相当(つかむ)。両手つまみ=大きさ・回転
- 呼び戻しボタンは素手には無い(誤爆しやすいジェスチャは入れない)。必要ならコントローラーを持ち替えて押す
- **注意: この段が一番実機依存**(つまみ判定の感度・切替の癖)。動作が怪しければ素直に一旦引っ込める

### 第4段のQuest確認項目
1. コントローラーを置いて手をかざすと、手の3Dモデルに切り替わるか
2. つまみでフィギュアをつかんで動かせるか
3. 両手つまみで大きさ・回転ができるか
4. コントローラーを持ち直すと元の操作に戻るか
