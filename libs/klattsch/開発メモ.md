# libs\klattsch カルテ(開発メモ)

最終更新: 2026-07-31 / 初版

## 何のために置いたか

自作ツール・ゲームの中で**レトロなロボ声を鳴らす**ための共通部品。
klattsch(https://github.com/tgies/klattsch )が **MIT License** なので同梱・再配布できる。
これにより「klatts.ch のサイトを開いて wav を書き出して置く」という手間が消え、
`robo.say("GAME OVER")` の1行で鳴るようになった。

## 中身

| ファイル | 何か |
|---|---|
| `klattsch.js` | 本家の `src/engine/` を**1枚のふつうのスクリプトに束ねたもの**。中身は無改変 |
| `robo.js` | この家用の包み紙。定型メッセージ20個と声のプリセット、再生・停止・wav書き出し |
| `LICENSE` | 本家のMITライセンス。**消さない**(再配布の条件) |
| `つかいかた.txt` | 組み込み方 |

## ★ なぜ束ねる必要があったか

本家の `src/engine/` は **ESモジュール**。
**ESモジュールは `file://` では CORS で読み込めない。**
この家のツールはHTML1枚をダブルクリックで開く運用なので、
モジュールのままでは動かない(教訓集の「file://ではWorkerが動かない」と同族の問題)。

→ import/export を外して依存順に連結し、IIFEで包んで `window.klattsch` に出す
**classic script** に変換した。

### 束ね方(作り直すとき)

1. 本家から `src/engine/` 一式を取る(raw.githubusercontent.com)
2. 連結順は依存順に:
   `banks/bundled.js` → `banks/index.js` → `dsp.js` → `phonemes.js`
   → `synth-core.js` → `sequencer.js` → `wav.js` → `kana.js`
3. `import` 行を削除、`export` を外す、IIFEで包んで `window.klattsch` に代入
4. **一番外側(行頭に空白のない)の宣言だけ**名前の衝突を検査する。
   関数の中のローカル変数まで見ると誤検出だらけになる(実際に1回引っかかった)
5. **`pronounce.js` は入れない。** npmの `cmu-pronouncing-dictionary`(巨大)が要る。
   英単語→発音記号の自動変換が要るときだけ検討する

束ねるスクリプトは使い捨てにした。手順は上記のとおり。

## 地雷・確認済みの事実

- **音はユーザー操作のあとしか鳴らない**(ブラウザ共通)。`robo` は AudioContext を
  遅延生成し `resume()` するが、それでも初回はクリック等が必要
- **音が鳴っているかは耳を使わず数値で確かめられる。** `renderToBuffer` の戻りの
  Float32Array の peak / RMS を測る。無音なら 0.00。
  実測: `HH AH L OW` → peak 0.85 / RMS 0.19、`GAME OVER` → peak 0.87 / RMS 0.18
- 日本語バンクは `[bank=ja-hecko-2026]` を文字列の先頭に置けば切り替わる
- `kanaToPhonemes()` が本家に入っているので、かな→発音記号は自前実装より
  こちらを使うほうが正しい(ロボ読みの画面側はまだ自前の表を使っている。統一の余地あり)

## 確認手順

1. `ツールボックス\ロボ読み\ロボ読み.html` をダブルクリック
2. 「▶ ここで喋る」を押す → 音が鳴るか
3. 定型メッセージを押してから「▶ ここで喋る」→ 声が変わるか
4. 「wav に保存」→ robo.wav がダウンロードされ、再生できるか

ロボ読みが**この部品の確認台**になっている(xr-pen に対する pen-quest と同じ役割)。
