# えのなか 開発メモ

背景の絵 1 枚の中を、VRM のキャラが歩く。絵を 3D に起こさない。絵はそのまま、カメラも動かさず、
「床がどこにあって、どれだけ奥にあるか」だけを決めて、その上を 3D のキャラに歩かせる。
カメラを固定したので、絵の質は 100% そのまま残る。

## ファイル

- `index.html` … 画面・キャラの動き・タップ・編集・保存・写真と録画
- `stage-core.js` … 中身。絵⇔床の変換、歩ける所の格子、道探し（A*）、タップ先の決め方、前に出すものの奥行き、保存データの検査。node でも読める
- `sample-scene.js` … お試しの絵（夏の広場）。同じカメラで描いて、床などの設定も描いた形からそのまま作る。画像ファイルは持たない
- `gait.js` … 歩き方。足を置く場所を先に決めて、脚の角度を逆算する。node でも読める
- `motions/` … 内蔵のうごき 13 個（`*.vrma`）と一覧 `index.json`。元のキーフレームは `motions/specs/*.json`
- `tools/build-motions.mjs` … specs から .vrma と一覧を作る（Text-To-VRMA を使う。下の「うごき」）
- `presets.js` … 用意した場面 3 つ（ひまわりの道・杉並木の神社・木造校舎の廊下）の設定。node でも読める
- `bg/` … その絵（1536×1024 の JPEG、各 330〜420KB）と一覧用の小さい絵。もらった PNG を JPEG にしただけ
- `lib/three-vrm-bundle.min.js` … three.js r186 と GLTFLoader と @pixiv/three-vrm 3.5.5・@pixiv/three-vrm-animation 3.5.5 を 1 本にまとめたもの（MIT、`lib/LICENSE-*.txt`）
- `models/sample.vrm` … お試しのキャラ。条件は `models/README.md`
- `sw.js`・`manifest.webmanifest`・`icon-*.png` … ホーム画面に置けるように
- `test/core.test.js`・`test/presets.test.js`・`test/gait.test.js`・`test/motions.test.js` … `node enonaka/test/core.test.js` のように走る

## しくみ

カメラは水平に向けて傾けない。地平線（目の高さ）は絵の中の水平な線になり、縦の線は縦のまま。アニメの背景の描き方と同じ。
決めるのは 3 つ：地平線の高さ、目線の高さ（m）、画角。

- 絵の点 (u, v) を高さ h の床に落とす：`t = (目線 − h) / (v − 地平線)`、`x = (u − 中央) × t`、`z = −焦点距離 × t`
- 人の背丈は「足元と地平線の距離」に比例する。画角によらない。目線と同じ背丈の人は、どこに立っても頭が地平線に来る
- three.js のカメラは、この式と同じになるように投影行列を直に入れている（地平線の高さはレンズを上下にずらした扱い）

キャラの見え方は 3D のまま（MToon）。光は前の上から 1 つと、まわりの明るさ。

## 床と段差

床は絵の上の多角形で、高さ（m）を持つ。世界の床に起こして 0.15m 角くらいの格子にする（格子は最大 12 万マス、奥行きは 60m まで）。

- 床が重なったら高い方。台の上面の絵は、手前の地面の絵とも重なるため
- 「通れない所」は高さに関係なく塞ぐ
- 隣のマスとの高さの差が 0.35m を超えたら通れない。だから台には階段を通って上がる
- 道は A*（8 方向、角は切らない）で探し、見通せる所は一直線にまとめる
- タップした点が複数の床の絵に入っていたら、高い床へ行く

## 隠れる

奥行きだけを書く透明な板を、キャラより先に描く。

- 床そのもの（水平な板、高さ −3cm）。台の向こうの地面を歩くキャラの足は、台の上面で隠れる
- 前に出すもの（絵と平行な板）。奥行きは多角形のいちばん下の点（床に接する所）で決まる。それより奥にあるキャラの部分が隠れる
- 台は、上面を「前に出す」に入れない。縦の面（正面・側面）だけを囲む。上面まで入れると、台の上に立ったキャラも隠れる
- 座っている間は、座った腰の位置が入っている「前に出すもの」を外す（ベンチに座ったキャラがベンチに隠れないように）

## キャラの動き

アニメーションのファイルは使わない。正規化した骨に毎回ゼロから角度を入れる（立つ・歩く・座る・手をふる・こちらを見る）。
VRM0 は前後が逆なので x と z の回りを反転する（`rotateVRM0` で向きはそろえたうえで）。

- 歩く（`gait.js`）：足をどこに置くかを先に決め、脚の角度は腰から足首への 2 関節の IK で逆算する
  - 1 歩きの 6 割は足が地面についている。ついている足は、体が進んだぶんだけ後ろへ下げる。歩きの位相は「進んだ距離 ÷ 歩幅」で進めるので、足は世界で止まって見える（お試しのキャラで、接地中の足の動きは体の進みの 0.6%）
  - 後ろ足は、つま先の付け根を支点にかかとを上げてからけり出す。前の足はかかとから着く（つま先が少し上を向く）
  - 振り出す足は低く前へ（脚の長さの 8.5%）。腰は片足で立つ間が高く、着地の直後が低い（上下 3.4cm）。立っている足の側へ少し寄る
  - 歩幅は脚の長さの 1.15 倍、速さは 1.1 倍（m/秒）。キャラが変わっても脚に合う
  - 段差：足ごとに床の高さを持つ。着いた足は着いた段の高さのまま、振り出す足は次に着く段の高さへ上げていく。体は両足の床の間
  - 歩きだしは少しずつ速く、着く手前 0.5m からゆっくり。その場で向きを変えるときは歩幅 0 の足踏み
  - 立ち止まると、脚はモデルの立った姿勢へ戻る
  - 腕は脚と逆に振り、胸を少しひねる
- 髪などの揺れもの：基準（center）を、体を 0.3 秒遅れで追いかける点にした。一定の速さで歩く間は髪が後ろへなびき続けず、歩きだし・止まる・曲がるときだけ揺れる
- 座る：太ももを水平、すねを垂直。腰を「太ももの長さ」だけ後ろへ、「すね＋足首の高さ」まで下ろす。手は太ももの上
- 手をふる：右腕。表情は happy。止まっている間は首と目でこちらを見る（目は `lookAt`）
- まばたきは 2〜6 秒おき

## 用意した場面

絵を見て、地平線・目線・画角・床・段差を決めた。決め方は絵ごとに違う。

- **ひまわりの道** … 校舎の左の壁の上下の線（1 階の軒と土台）を伸ばした交点が地平線（y=660）。右の壁の線はほぼ水平で、2 つの消失点の離れ方から画角 64°。
  目線 1.6m にすると、道幅 2.7m・柵 1.3m・入口 2.7m になる。床は道と校舎の前の空き地。人の頭はどこに立っても地平線にそろう
- **杉並木の神社** … 絵なので、段の縁の線と左右の端の線の遠近が合わない（全部を 1 つの立体に合わせると画角 130° 超）。
  そこで灯籠を 1.8m、段の幅を人の約 3.7 倍とみなして、各段に立ったときの背丈を先に決め（`0.435 × (v − 364)` px）、段の高さを逆算した。
  段の縁の y は明るさの山から拾った（981, 923, 873, … 660）。地平線 y=560、目線は一番下の段から 2.43m。段差は 0.09〜0.13m の 13 段、
  踊り場（灯籠の立つ両脇まで）、社殿への 9 段（奥行き 15.1m から 0.3m ずつ、0.056m ずつ）、社殿の前。灯籠と賽銭箱は「前に出す」と「通れない」
- **木造校舎の廊下** … 左右の壁の根元の線が (373, 411) で交わる。目線 1.5m で、幅 2.2m・奥の扉まで 19m・天井 3.4m。床は壁から 0.25m 内側

光の色味は場面ごと（ひまわり 暖かい 25、神社 寒い 20・明るさ 85%、廊下 暖かい 60・明るさ 85%）。
直した設定は場面ごとに残る。「この場面を最初の設定に戻す」で `presets.js` の値に戻る。

## うごき（VRMA）

「🎬 うごき」から選ぶと、こちらを向いてからそのうごきをする。座っていたら先に立つ。ぶらぶら中も、ときどき（3 割）うごきをやる（ダンスは除く）。
とちゅうで床をタップ・キャラをタップ・別のうごきを選ぶと、0.3〜0.45 秒かけてなめらかにやめる・入れかえる。

内蔵は 13 個：おじぎ、喜んでジャンプ、両手で手をふる、のび、考えごと、遠くを見る、拍手、ガッツポーズ、しょんぼり、びっくり、しゃがむ、おしゃべり、ダンス（くり返し、120 拍）。
自分の .vrma も追加できる（IndexedDB の `userMotions`）。Text-To-VRMA のデスクトップ版で作ったものをそのまま入れられる。

### 再生のしかた

毎フレーム、まず手続きの姿勢（立つ・歩く・座る、`pose()`）を骨に入れ、そのあとクリップの値へ重み w で寄せる（`applyAct`）。
クリップは `createVRMAnimationClip` で作るが、AnimationMixer は使わない。各トラックの補間器（`track.createInterpolant()`）を時刻を指定して直接読む。
- AnimationMixer は「前のフレームと同じ値なら骨に書かない」ので、毎フレーム手続きの姿勢で上書きする作りだと、止まっている区間（あごに手を当てたまま等）でモーションが消える
- 指・つま先など手続きで動かさない骨は、毎フレームまっすぐに戻してから重ねる（モーションが終わったあと指が曲がったまま残らないように）
- 表情（happy・blink など）も同じく、こちらの値からクリップの値へ w で寄せる
- 別のうごきへは、前のクリップと新しいクリップのあいだを 0.3 秒で混ぜてから、手続きの姿勢と w で混ぜる

### Text-To-VRMA で作る

内蔵のうごきは Text-To-VRMA（https://github.com/Kirakun0328/text-to-vrma、MIT、© Kiratchi）の「LLM キーフレーム」方式で作った。
- Text-To-VRMA は、AI が骨ごとのオイラー角のキーフレーム JSON（モーション spec）を書き、それを検査・補正して VRMA に書き出す。AI は OpenAI・Claude・Codex から選べる
- ここでは API キーがないので、その AI の役（spec を書く）を Claude Code が受け持った。Text-To-VRMA のシステムプロンプトの決まり（座標・可動域・解剖学メモ）に従って書き、
  Text-To-VRMA 本体の `validateSpec`（可動域のクランプとガード）→ `softenMotion`（全身のなめらか補正）→ `buildVRMA`（VRMA 書き出し）に通した
- もう一つのエンジン ARDY（NVIDIA のモーション生成、モーションキャプチャ品質）は、約 20GB のモデルと GPU が要り、作業環境から Hugging Face にもつながらないので使っていない
- 脚と手の位置が大事なうごきは、角度を当てずっぽうにせず逆算して数値を決めた（足首を置く場所から脚の角度、手首を置く場所から腕の角度）。
  キーとキーのあいだで足が沈まないよう、脚のキーは 0.05 秒ごとに逆算して打っている。ひじは前へ曲がる蝶番、上腕は Text-To-VRMA の可動域（各軸 ±75°、ひじを深く曲げる腕は上げ 58° まで、ひじ 135° まで）に収めた
- Text-To-VRMA のガードのため、あごにこぶしを真下から当てる形は作れない（ひじ 140° が要る）。考えごとは、口元にこぶしを寄せる形にした

作り直し：
```sh
git clone https://github.com/Kirakun0328/text-to-vrma.git && (cd text-to-vrma && npm install)
node enonaka/tools/build-motions.mjs ./text-to-vrma
```
`validateSpec` が値を丸めたら「丸めた」と出る（書いた値が可動域の外だった）。

## 編集（つくる）

地平線（ドラッグ。補助線 2 本の交点からも求まる）／床（歩ける・通れない・高さ）／前に出す／すわる（足を置く点と向き）／見え方（キャラの大きさ＝目線の高さ、遠近感＝画角、キャラの明るさ、光の色味）。

点は 0〜1 に割った値で持つので、絵の大きさによらない。編集中はキャラを絵の上の同じ場所に残す（設定を変えると世界の座標が動くため）。

## 保存

IndexedDB（`enonaka`）。使えなくても動く。

- `current` … いま開いている場面（`sample`・`himawari`・`jinja`・`rouka`・`custom`）
- `bg` … 自分の絵（長い辺を 2048 に縮めた JPEG）
- `scene` … 自分の絵の設定。`scene:<場面>` … お試しの広場と用意した場面を直した設定（前の版の `sampleScene` も読む）
- `vrm` … 選んだ VRM。なければお試しのキャラ
- `prefs` … ぶらぶらの入・切

絵は 1 枚ぶんだけ持つ。別の絵を選ぶと前の設定は消える。

## 写真と録画

絵（元の解像度から縮める）とキャラの canvas を 1 枚に重ねる。長い辺 1920 まで。
録画は `captureStream(30)` を MediaRecorder で。iPhone は mp4、ほかは webm。60 秒で止まる。
保存は、できあがりを見せてから「保存する・送る」を押してもらう（iPhone の共有シートは指で押した直後でないと開かないため）。

## 確かめたこと（ヘッドレス Chromium）

お試しの広場で：台をタップ → 階段 2 段を踏んで台の上へ／ピンクの印 → ベンチまで歩いて向きを変えて座る（手は太もも）／
キャラをタップ → 笑って手をふる／ベンチの裏 → 背もたれから下が隠れる／街灯の裏 → 柱の太さだけ隠れる。
写真（1920×1080）、録画、自分の絵の取り込み、VRM の入れかえ、読み直しても絵とキャラが残ること。iPhone の実機ではまだ見ていない。

## まだやっていないこと

- 拡大して点を打つ（縦向きのスマホで横長の絵だと、点が細かい）
- 坂（床は水平だけ）。階段は高さの違う床を並べて作る
- 絵の明るさや色にキャラを合わせる（明るさのつまみだけ）
- 自分の絵を何枚も持つ・場面を書き出す（用意した場面は別々に持てる）
- アプリの中で文章からうごきを作る（Text-To-VRMA と同じく Claude API を端末から呼べば作れるが、API キーを端末に置くことになる）
